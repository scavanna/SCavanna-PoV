# 14. Arquitectura de operación sobre tecnologías de un cliente Full Microsoft

**Propósito:** traducir los controles `CT-01..21`, las detecciones `DE-01..13` y los playbooks `PB-01..07` en un **modelo concreto de operación diaria, trimestral y de crisis** para una organización que estandariza su seguridad, productividad, nube, datos e IA sobre plataforma Microsoft (**Full Microsoft**), sin confundir licenciamiento disponible con control desplegado o probado.

## 1. Qué significa operar como cliente Full Microsoft en resiliencia ante ransomware

Un cliente Full Microsoft cuenta típicamente con **Microsoft 365 E5** (o **E7** / complementos **Entra Suite**, **Intune Suite**, **SharePoint Advanced Management**, **Agent 365**), **Azure** con **Microsoft Defender for Cloud** (incluyendo **Defender for Servers Plan 2**, **Defender for Storage/Databases/Containers/AI** y **Defender for IoT** cuando existe OT), **Microsoft Sentinel** + **Azure Logic Apps**, **Microsoft Security Copilot**, **Azure Backup** (bóvedas inmutables + *Resource Guard*), **Azure Site Recovery** y **Microsoft 365 Backup**.

El valor diferencial frente al ransomware operado por humanos (y frente a la doble extorsión sin cifrado) surge de **cuatro integraciones nativas que deben configurarse y probarse explícitamente**:
1. **Plano único de identidad y acceso condicional (`Entra ID` + `MDI` + `PIM` + `GSA` + `Entra Agent ID`):** bloquea phishing de credenciales con FIDO2/Passkeys (`K33`), elimina privilegios permanentes (`K34`), acelera revocación con CAE y extiende el control a cargas de trabajo y agentes (`K50`).
2. **Correlación e interrupción cruzada a velocidad de máquina (`Defender XDR` + `Sentinel` + `Security Copilot`):** une señales de correo, endpoint, identidad híbrida, SaaS, storage y nube para ejecutar *Automatic Attack Disruption* sobre cuentas y hosts comprometidos mientras el SOC valida alcance (`K42`, `K45`, `K55`).
3. **Visibilidad y freno de exfiltración y evidencia legal (`Purview MIP` + `DLP` + `Insider Risk` + `Audit Premium` + `eDiscovery Premium`):** protege datos sensibles antes y durante el incidente (`K37`, `K52`), preserva cadena de custodia con hash y *legal holds* (`CT-14`, `K57`) y respalda decisiones regulatorias (`K61`).
4. **Recuperación en dos velocidades con separación de planos (`Azure Backup Immutable + MUA`, `ASR`, `M365 Backup` y `AD Forest Recovery`):** impide que un Global Admin o Subscription Owner comprometido borre las copias y permite restaurar tanto infraestructura crítica como colaboración masiva dentro de RTO/RPO (`K28`, `K30`, `K47`).

## 4. Seis decisiones de arquitectura que evitan fallos catastróficos en clientes Full Microsoft

1. **Separar el plano de custodia de respaldos (`Resource Guard` / `MUA`):** alojar el `Resource Guard` de Azure Backup en otra suscripción y, para activos Tier-0, bajo control administrativo segregado para que el compromiso de un administrador productivo no permita desactivar inmutabilidad ni acortar retención (`CT-02`, `DE-05`, `PB-03`).
2. **Posicionar `Microsoft 365 Backup` frente a `Files Restore`:** usar `Files Restore` y versionado para incidentes acotados de usuario/sitio dentro de 30 días, pero evaluar `Microsoft 365 Backup` cuando el BIA exija restaurar cientos o miles de sitios/buzones en pocas horas sin degradar RTO (`CT-20`).
3. **Tratar `Active Directory` híbrido como activo Tier-0 de propagación:** un atacante con dominio en AD DS cifra servidores on-premises aunque Entra ID tenga MFA; exigir sensor v3.x de **Defender for Identity** en todos los DCs/AD FS/AD CS, bloqueo de uso remoto de cuentas locales, LAPS y prueba aislada de *AD Forest Recovery* (`CT-03`, `CT-04`).
4. **Cerrar la brecha entre revocación de Entra y sesiones de aplicaciones (`MS-10`):** combinar **CAE** y **Token Protection** con deaprovisionamiento rápido y control de sesión en **Defender for Cloud Apps** para cortar descargas activas en SaaS no compatibles con CAE (`PB-02`, `PB-04`).
5. **Gobernar costos y disponibilidad de `Security Copilot` y `Sentinel`:** aprovisionar SCU con presupuesto/alertas, separar logs de alto volumen en niveles adecuados y no depender de `Application Insights` ni capacidades de pago por uso en suscripciones con límite de gasto de laboratorio (`NT-01 M3`, `NT-04 I2, M7`).
6. **Impedir que Copilot y agentes amplifiquen sobreexposición o extorsión:** remediar permisos excesivos con **SharePoint Advanced Management** antes de escalar agentes, exigir identidad y propietario humano en **Entra Agent ID / Agent 365** y probar que cada proceso crítico sigue operando si se apagan todos los agentes (`CT-21`, `PB-07`, `K56`).
