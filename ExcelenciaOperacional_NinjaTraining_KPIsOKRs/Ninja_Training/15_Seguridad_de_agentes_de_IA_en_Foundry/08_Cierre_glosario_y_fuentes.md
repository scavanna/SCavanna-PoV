## ¿Y ahora?

Ser Ninja de la seguridad de agentes no es un estado, es un hábito mensual: repetir la batería de ataques y el red teaming en cada versión, revisar el volumen bloqueado por los guardrails y las alertas de IA con su contexto de usuario, mirar el consumo de tokens por consumidor, recertificar los agentes con su sponsor, cerrar hallazgos de Azure Policy y de Defender CSPM y explicar la tendencia al comité. Después de Microsoft Ignite (17 al 20 de noviembre de 2026), verifica en especial el estado de los guardrails de agentes y de la intervención en herramientas, PII y Task Adherence, los escaneos agénticos y programados del AI Red Teaming Agent, el AI gateway de Foundry y el nivel AI Gateway de APIM, la red administrada y Network Security Perimeter para Foundry, Operate del Control Plane, OBO con identidad de agente, la memoria, el Copilot harness, Toolbox, el precio de los agentes alojados, el escaneo de modelos, el middleware de Purview y el modelo de identidad de los agentes.

Próximos pasos: el examen [SC-500](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/sc-500) para ingeniería de seguridad, el [AI-103](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ai-103) para desarrollo (tiene guía en español), el [SC-100](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/sc-100) o el [AB-100](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/ab-100) para arquitectura, y las playlists y Practice Assessments de [AI Skills Navigator](https://aiskillsnavigator.microsoft.com/). En la serie, profundiza lo que aquí solo se integra: Entra: identidad y agentes (track de agentes), Defender for Cloud (cargas de IA, APIs y DevOps security), Purview DSPM y seguridad de datos para IA, Purview eDiscovery y Audit, Purview Compliance Manager, Seguridad de Microsoft 365 Copilot, agentes y Copilot Studio, Microsoft Sentinel, Defender XDR y Security Copilot. El [plan integrado](../Plan_Arquitectura_Segura_Agentes_IA_Azure.md) ordena todo por fases y por rol.

Si encuentras un enlace roto, un dato desactualizado o un recurso que debería estar aquí, anótalo y compártelo con tu equipo: esta guía está pensada para mantenerse viva con revisiones periódicas, como los Ninja originales. Para mantenerte al día, sigue el resumen mensual del [Microsoft Foundry Blog](https://devblogs.microsoft.com/foundry/category/whats-new/), las [actualizaciones de Azure por RSS](https://www.microsoft.com/releasecommunications/api/v2/azure/rss) y [The Azure Security Podcast](https://azuresecuritypodcast.azurewebsites.net/); para preguntas técnicas, Microsoft Q&A, el Discord de Microsoft Foundry y las sesiones de Microsoft Reactor en español son los mejores lugares.

## Glosario

| Término | Definición |
|---|---|
| Microsoft Foundry | Plataforma de Azure para construir, desplegar y operar modelos, agentes y aplicaciones de IA; antes Azure AI Foundry (y antes Azure AI Studio). Su recurso es de tipo Microsoft.CognitiveServices/accounts y la familia de servicios se llama ahora Foundry Tools. |
| Recurso y proyecto de Foundry | El recurso es el límite administrativo, de seguridad, de red y de monitoreo; el proyecto es un subámbito para organizar el trabajo y el acceso, y comparte almacenamiento, conversaciones e índices entre sus agentes. La baseline recomienda un recurso dedicado por carga de producción. |
| Foundry (classic) y proyectos basados en hub | Modelo anterior de Foundry, basado en hubs de Azure Machine Learning. No funciona en el portal nuevo y conserva los Assistants y los agentes v1 hasta su migración. |
| Foundry Models | Catálogo de modelos de Foundry. Los vendidos por Azure tienen soporte, SLA y compromisos de privacidad de Microsoft; los de socios y comunidad (por ejemplo, Anthropic o Hugging Face) se rigen por los términos del proveedor. |
| Tipos de despliegue | Global (cualquier región), Data Zone (solo dentro de EE. UU., la UE o Asia-Pacífico) y Standard o Regional (dentro de la geografía). Los datos en reposo quedan en la geografía elegida y no hay Data Zone de Latinoamérica. |
| Foundry Agent Service | Runtime administrado de agentes de Foundry sobre la Responses API, GA en su nueva generación desde el 16 de marzo de 2026. Es la «Agent Service v2» de la infografía; los agentes clásicos se retiran el 31 de marzo de 2027. |
| Prompt agent, hosted agent y workflow agent | Prompt agent: agente declarativo en cómputo de Microsoft. Hosted agent: tu código y tu framework en un sandbox por sesión aislado por hipervisor (GA el 9 de julio de 2026). Workflow agent: flujo declarativo de Foundry en vista previa que se retira el 1 de diciembre de 2026. |
| Configuración básica y estándar | En la básica, el estado del agente vive en almacenamiento multiinquilino de Microsoft; en la estándar, en tu Cosmos DB, tu Storage y tu AI Search, con CMK y la posibilidad de red privada de salida. Las capability settings de un proyecto no se pueden cambiar después. |
| Microsoft Agent Framework | SDK de código abierto para .NET y Python que unifica Semantic Kernel y AutoGen (versión 1.0 en abril de 2026), con middleware, workflows, humano en el bucle y OpenTelemetry. Por defecto, sus herramientas de función se ejecutan sin aprobación. |
| Toolbox | Endpoint MCP único de Foundry que centraliza credenciales, versiones y políticas de herramientas; una página lo da como GA y otra como vista previa. |
| MCP (Model Context Protocol) | Estándar abierto para que los agentes descubran y llamen herramientas. En Foundry, un `allowed_tools` vacío permite todas las herramientas y conviene declarar siempre `require_approval`. |
| A2A (Agent2Agent) | Protocolo para que un agente llame a otro. Foundry lo ofrece como herramienta (GA con el protocolo 1.0) y API Management como API administrada; el llamador necesita el rol Foundry Agent Consumer sobre el agente destino. |
| Foundry IQ | Bases de conocimiento sobre Azure AI Search que pueden sincronizar ACL, respetar etiquetas de Purview y consultar con la identidad del usuario, solo si la fuente lo admite y se configuró la sincronización. |
| Guardrail | Colección con nombre de controles de seguridad de contenido (antes content filters) que se asigna a un despliegue de modelo o a un agente; en la API es una RAI policy. El del agente reemplaza por completo al del modelo. |
| Punto de intervención | Lugar donde un guardrail inspecciona: entrada del usuario, llamada a herramienta, respuesta de herramienta y salida. Los dos de herramientas son solo para agentes, están en vista previa y cubren ocho herramientas, no MCP. |
| Prompt Shields | Clasificadores de Azure AI Content Safety contra ataques del usuario (jailbreak, UPIA, activo por defecto) y en documentos (inyección indirecta o XPIA, apagado por defecto). Se entrenaron principalmente en inglés. |
| Spotlighting | Técnica que marca o codifica el contenido de terceros para que el modelo lo trate como dato y no como instrucción. En Foundry está en vista previa, solo para Chat Completions y no aplica a agentes. |
| Task Adherence | Control en vista previa que detecta llamadas a herramientas desalineadas con la intención del usuario para bloquearlas o escalarlas a revisión humana; puede procesar datos en EE. UU. o la UE. |
| Groundedness detection | Detección de respuestas no sustentadas en las fuentes, en vista previa, solo en inglés y sin efecto en agentes; se retira el 30 de abril de 2027. |
| Customer Copyright Commitment (CCC) | Compromiso contractual de Microsoft de defender al cliente ante reclamos de derechos de autor por salidas de Azure OpenAI, condicionado a mitigaciones como el material protegido en modo filtro y el informe de pruebas. |
| Microsoft Entra Agent ID | Tipo de identidad de Entra para agentes: un blueprint (plantilla con credencial federada y permisos heredables) y una identidad por agente, con sponsor y owner. Nace sin permisos; acceso condicional, ID Protection y gobierno para agentes exigen Agent 365 o E7. |
| OBO (on-behalf-of) | Flujo de OAuth en el que el agente obtiene un token para actuar en nombre del usuario, de modo que la herramienta aplica los permisos de esa persona. En Foundry, OBO con identidad de agente está en vista previa. |
| Autenticación sin claves | Uso exclusivo de Entra ID e identidades administradas, con la autenticación local deshabilitada (`disableLocalAuth=true`). Con una clave se obtiene acceso total, sin roles, sin auditoría por persona y sin acceso condicional. |
| Roles de Foundry | Foundry User, Foundry Project Manager, Foundry Account Owner y Foundry Owner (antes Azure AI User, Project Manager, Account Owner y Owner, con los mismos IDs) y el nuevo Foundry Agent Consumer, que solo permite invocar agentes. |
| AI gateway | Capacidades de Azure API Management para gobernar APIs de modelos, servidores MCP y APIs A2A (límites de tokens, seguridad de contenido, métricas y registro). No confundir con el AI gateway asociado desde Foundry ni con el nivel AI Gateway dedicado, ambos en vista previa. |
| llm-token-limit y llm-content-safety | Políticas de API Management para limitar tokens por minuto y cuotas por consumidor (429 y 403) y para enviar prompts, respuestas y mensajes de MCP y A2A a Content Safety; su verificación shield-prompt viene apagada. |
| Azure API Center | Inventario y registro privado de APIs, servidores MCP y agentes, con evaluación de agentes y sincronización desde API Management y Git. |
| Inyección de VNet y red administrada | Dos formas de controlar la salida del Agent Service: tu propia VNet con una subred delegada (definida al crear el recurso) o una red administrada por Microsoft con egreso aprobado (CLI en vista previa, no se puede deshabilitar). |
| Network Security Perimeter (NSP) | Perímetro lógico para servicios PaaS fuera de una VNet, con modos Transition (antes Learning) y Enforced. Está en GA, pero los agentes estándar aislados de Foundry usan Private Link, que tiene precedencia. |
| Private endpoint | Interfaz de red privada de un servicio PaaS dentro de tu VNet, con su zona DNS privada; junto con el acceso público deshabilitado, evita la exposición directa de Foundry y de sus dependencias. |
| WAF y DRS 2.2 | Azure Web Application Firewall en Application Gateway v2 o Front Door Premium, con el Default Rule Set 2.2 basado en OWASP CRS 3.3.4. No tiene reglas para prompt injection y los chats largos generan falsos positivos. |
| DDoS Network Protection e IP Protection | Planes de Azure DDoS Protection por red virtual o por IP pública; la protección de infraestructura es gratuita. No existe un nivel «Advanced» y no cubren los niveles v2 de API Management. |
| Foundry Control Plane | Experiencia de gobierno de Foundry: inventario y operación de agentes (iniciar, detener, bloquear), políticas de guardrails sobre Azure Policy, postura de Defender y activación de Purview. Su parte Operate está en vista previa. |
| AI-SPM y AI BOM | Postura de seguridad de IA de Defender CSPM: descubre los componentes, datos y artefactos de IA (AI BOM) desde el código hasta la nube y calcula rutas de ataque. Desde el 1 de julio de 2026 la postura por agente exige Agent 365. |
| Defender for AI Services | Plan de Defender for Cloud que detecta amenazas en tiempo de ejecución sobre los prompts y respuestas de Foundry Models (antes «Defender for AI» en la infografía). Analiza solo texto y cuesta 0,0008 USD por 1.000 tokens. |
| UserSecurityContext | Objeto que la aplicación envía con cada llamada a Azure OpenAI (EndUserId, SourceIP, applicationName) para que las alertas de Defender identifiquen usuario y aplicación. Si un campo está mal escrito, la llamada funciona igual y el contexto se pierde en silencio. |
| AppGenAIContent | Tabla de Azure Monitor a la que van, desde el 30 de septiembre de 2026, los prompts, respuestas, instrucciones y argumentos de herramientas de las trazas; se protege con el rol Privileged Monitoring Data Reader. |
| OpenTelemetry GenAI | Convenciones semánticas de OpenTelemetry para IA generativa (spans como invoke_agent o execute_tool) que usan Foundry y Agent Framework; la captura de contenido se controla con OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT. |
| AI Red Teaming Agent y ASR | Capacidad de Foundry que combina PyRIT con los evaluadores de riesgo para atacar modelos y agentes y calcular el Attack Success Rate (ASR), el porcentaje de ataques que tuvo éxito. |
| PyRIT | Python Risk Identification Tool, herramienta abierta del Microsoft AI Red Team (repositorio microsoft/PyRIT) para automatizar pruebas adversariales contra tus propios modelos y agentes; la v1.1.0 es del 4 de septiembre de 2026. |
| Denial of wallet y LLMjacking | Abuso que dispara el gasto de IA con solicitudes masivas o repetidas, y robo de capacidad de IA con claves o credenciales filtradas, como hizo Storm-2139. Se previenen con autenticación sin claves, límites de tokens y presupuestos. |
| Tool poisoning y rug pull | Instrucciones ocultas en la descripción o los resultados de una herramienta, y cambio de una herramienta ya aprobada. Se mitigan revisando descripciones como código, fijando versiones y exigiendo aprobación ante cambios. |
| Microsoft Agent 365 y Microsoft 365 E7 | Plano de control de agentes (15 USD por usuario al mes) y suite que lo incluye (99 USD por usuario al mes). Quedan fuera de alcance de este programa, que solo indica qué capacidad los exige y su alternativa. |
| OWASP, MITRE ATLAS y taxonomía de Microsoft | Marcos de amenazas que usa el programa: OWASP Top 10 for LLM Applications 2025 (LLM01 a LLM10), OWASP Top 10 for Agentic Applications 2026 (ASI01 a ASI10), MITRE ATLAS (datos v2026.10) y la taxonomía de modos de fallo en sistemas agénticos v2.0 del AI Red Team. |
| MCSA | México, Centroamérica y Sudamérica, sin Brasil: la región a la que se dirige la serie. Para Foundry importa porque no hay Data Zone de Latinoamérica y varias funciones llegan a Brazil South antes que a México Central. |

## Metodología y fuentes

Esta guía se construyó con líneas de investigación en paralelo sobre fuentes públicas: la forma y la historia del Ninja oficial, cada nivel técnico, la operación y la comunidad. Cada enlace se registró solo si apareció literalmente en un resultado de búsqueda o en una página leída, y luego se consolidó, se depuró y se verificó. Se descartaron recursos retirados, alojados en espacios no públicos o duplicados. Fecha de corte: 7 de noviembre de 2026.

Puntos a confirmar en fuentes oficiales antes de recomendarlos:

- **Modelo de identidad de los agentes: tres fuentes y dos planos.** La página de identidad de agentes (28-oct-2026) dice que cada agente nuevo recibe su propio blueprint e identidad al crearse, que la identidad compartida del proyecto queda solo para agentes legacy y que no se asignan roles automáticamente; la página de gobierno de Entra Agent ID dice que los agentes no publicados comparten la identidad por defecto del proyecto y que publicar crea una dedicada; y la arquitectura baseline indica que los prompt agents comparten la identidad administrada del proyecto para llegar a Cosmos DB, Storage y AI Search. Son planos distintos: el acceso de la plataforma a sus dependencias frente a la identidad que el agente usa con sus herramientas. Esta guía enseña ambos, pide comprobarlo en el laboratorio y revalidarlo después de Ignite ([identidad de agentes](https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-identity), [gobierno de Agent ID](https://learn.microsoft.com/en-us/entra/id-governance/agent-id-governance-overview), [baseline](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/architecture/baseline-microsoft-foundry-chat)).
- **Estado del Foundry Control Plane.** El anuncio del 16-mar-2026 dio por GA las evaluaciones, el tracing y el monitoreo, pero la tabla oficial del portal (14-ago-2026) mantiene en vista previa Operate (Overview, Assets y Compliance), Monitoring y Manage AI Gateway. Se enseña como GA parcial (observabilidad) y vista previa de inventario y cumplimiento ([anuncio](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/building-production-ready-secure-observable-ai-agents-with-real-time-voice-with-/4501074), [tabla de estados](https://learn.microsoft.com/en-us/azure/foundry/concepts/general-availability)).
- **Red administrada de Foundry.** La página de Learn no la rotula como vista previa y el resumen de mayo de 2026 del Foundry Blog la anunció en GA, pero la CLI está en vista previa, el portal no la crea y el repositorio de plantillas marca la 18 como «(preview)». Tampoco se puede deshabilitar ni migrar desde una VNet propia, y no registra el tráfico saliente. Verifica su estado en tu región antes de diseñar con ella ([red administrada](https://learn.microsoft.com/en-us/azure/foundry/how-to/managed-virtual-network), [resumen de mayo](https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-may-2026/), [plantillas](https://github.com/microsoft-foundry/foundry-samples/tree/main/infrastructure/infrastructure-setup-bicep/15-private-network-standard-agent-setup)).
- **Network Security Perimeter para Foundry.** NSP está en GA en todas las regiones públicas (página del 2-oct-2026) y la página de AI Search declara GA su soporte para recursos AIServices, pero las versiones de 2025 de la página de Foundry pedían el flag OpenAI.NspPreview, las versiones localizadas siguen diciendo vista previa y la vigente no muestra etiqueta. Además, los agentes estándar con aislamiento completo usan Private Link, que tiene precedencia, y no requieren NSP. Esta guía lo trata como no GA para Foundry ([NSP en Foundry](https://learn.microsoft.com/en-us/azure/foundry/how-to/add-foundry-to-network-security-perimeter), [conceptos de NSP](https://learn.microsoft.com/en-us/azure/private-link/network-security-perimeter-concepts), [NSP en AI Search](https://learn.microsoft.com/en-us/azure/search/search-security-network-security-perimeter)).
- **Política de elegibilidad de modelos.** Figura como GA en la página de políticas de modelos (18-ago-2026) y como «[Preview]» en copias de la referencia de políticas ([políticas de modelos](https://learn.microsoft.com/en-us/azure/foundry/how-to/model-deployment-policy), [referencia de políticas](https://learn.microsoft.com/en-us/azure/ai-services/policy-reference)).
- **Precio de los agentes alojados.** Son GA desde el 9-jul-2026, pero la página de precios mostraba N/A para vCPU-hora y GiB-hora al 7-nov-2026; las tarifas que publican partners en sus blogs no son oficiales y este programa no las cita ([precios](https://azure.microsoft.com/en-us/pricing/details/foundry-agent-service/), [blog del partner](https://www.bighatgroup.com/blog/microsoft-foundry-hosted-agents-enterprise-guide-april-2026/)).
- **Audiencia del token.** El portal nuevo documenta la audiencia `ai.azure.com/.default` (con https) y la experiencia clásica, `cognitiveservices.azure.com/.default`: verifica la que usa tu SDK antes de diagnosticar un error 401 ([autenticación en Foundry](https://learn.microsoft.com/en-us/azure/foundry/concepts/authentication-authorization-foundry)).
- **Nombres de roles en transición.** Azure AI User y Foundry User, y el resto de pares, pueden coexistir en el portal, la CLI y las plantillas antiguas: asigna siempre por GUID ([roles de Foundry](https://learn.microsoft.com/en-us/azure/foundry/concepts/rbac-foundry)).
- **Brechas de disponibilidad para MCSA.** No hay Data Zone de Latinoamérica; la red administrada admite Brazil South pero no México; la plantilla 15 admite brazilsouth y no mexicocentral; la memoria de agentes está en Brazil South y no en México; AI Landing Zones no lista regiones de MCSA (ni East US 2) para el despliegue completo; el nivel AI Gateway de APIM solo existe en East US 2 y Sweden Central; las pruebas agénticas de red teaming en la nube solo corren en East US 2, France Central, Sweden Central, Switzerland West y North Central US; y Computer Use (página clásica) en eastus2, swedencentral y southindia. La residencia depende de toda la ruta: gateway, backends y registros ([tipos de despliegue](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/deployment-types), [memoria](https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/what-is-memory), [AI Landing Zones](https://github.com/Azure/AI-Landing-Zones), [nivel AI Gateway](https://learn.microsoft.com/en-us/azure/api-management/ai-gateway-overview), [AI Red Teaming Agent](https://learn.microsoft.com/en-us/azure/foundry/concepts/ai-red-teaming-agent)).
- **Acceso condicional y patrón OBO.** El acceso condicional para identidades de agente exige Microsoft 365 E7, o Agent 365 más Entra ID P1 o Microsoft 365 E3; las políticas sobre usuarios, incluido el patrón OBO que se dirige a usuarios, usarían el acceso condicional clásico con P1. Esa lectura del OBO es una interpretación de la página de acceso condicional para agentes: confírmala con tu equipo de licenciamiento ([acceso condicional para agentes](https://learn.microsoft.com/en-us/entra/identity/conditional-access/agent-id)).
- **Licencias de identidad para agentes en capas.** La página de administración pide Entra ID P1 para configurar el acceso condicional y Entra ID P2 para ver los informes de ID Protection de agentes durante la vista previa; la de acceso condicional exige además E7 o Agent 365; y la de ID Protection anuncia que requerirá Agent 365 «pronto», sin fecha. Esta guía enseña las tres capas y pide revalidarlas ([administración de identidades de agente](https://learn.microsoft.com/en-us/entra/agent-id/manage-agent-identities-admin), [agentes riesgosos](https://learn.microsoft.com/en-us/entra/id-protection/concept-risky-agents)).
- **Purview para Foundry: alcance real de la DLP.** La integración no admite aislamiento de red; las políticas solo se aplican con tokens de Entra del usuario en /chat/completions y, con otros métodos, solo queda la visibilidad en Audit; y la DLP actual solo bloquea prompts por tipos de información confidencial para una app registrada en Entra, configurada por PowerShell. Hay riesgo de una falsa sensación de DLP en los agentes ([Purview desde el Control Plane](https://learn.microsoft.com/en-us/azure/foundry/control-plane/how-to-manage-compliance-security), [Purview para Foundry](https://learn.microsoft.com/en-us/purview/ai-azure-foundry)).
- **¿Purview recibe datos de los agentes de Foundry?** La página de Defender for Cloud dice que la integración de Purview no incluye datos ni contexto de agentes de Foundry; la del Control Plane dice que fluyen los datos de todas las aplicaciones y agentes de la suscripción. Lo más probable es que la diferencia sea entre el método antiguo (desde Defender, en desuso) y el nuevo: esta guía enseña el nuevo y pide validarlo en el laboratorio ([Defender for AI Services](https://learn.microsoft.com/en-us/azure/defender-for-cloud/ai-onboarding), [Control Plane](https://learn.microsoft.com/en-us/azure/foundry/control-plane/how-to-manage-compliance-security)).
- **Facturación de las políticas de Purview para Foundry.** La página de Purview habla solo de pago por uso; la del Control Plane admite pago por uso o una suscripción de Agent 365. Sin ninguno de los dos, solo funciona Audit ([Purview para Foundry](https://learn.microsoft.com/en-us/purview/ai-azure-foundry), [Control Plane](https://learn.microsoft.com/en-us/azure/foundry/control-plane/how-to-manage-compliance-security)).
- **DLP en tiempo de ejecución para prompts de agentes.** El blog de Build 2026 la asocia a Agent 365, pero no se reverificó su alcance exacto para agentes de Foundry ni la cobertura de DSPM o Insider Risk para agentes con E7: no se enseña sin confirmar. La alternativa documentada son las APIs de Purview y el middleware de Agent Framework, que exige Microsoft 365 E5 y pago por uso y está en vista previa ([Build 2026](https://www.microsoft.com/en-us/security/blog/2026/06/02/microsoft-build-2026-securing-code-agents-and-models-across-the-development-lifecycle/), [middleware de Purview](https://learn.microsoft.com/en-us/agent-framework/integrations/by-component/middleware/purview)).
- **CMK por región.** La versión clásica advierte que la CMK solo está disponible en regiones seleccionadas por la capacidad de AI Search; la vigente no lo repite. Valida la región antes de comprometerte, porque la CMK de un proyecto no se revierte ([CMK](https://learn.microsoft.com/en-us/azure/foundry/concepts/encryption-keys-portal)).
- **Retención del monitoreo de abuso.** La página vigente de privacidad no indica un plazo de retención (versiones antiguas hablaban de 30 días): no afirmes un número sin fuente actual ([privacidad](https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/openai/data-privacy)).
- **Alcance de los compromisos de privacidad, del CCC y de algunos controles.** Están escritos para los modelos vendidos por Azure y Azure OpenAI; los modelos de socios (por ejemplo, Claude) y los abiertos se rigen por los términos del proveedor y Microsoft no los evalúa; las listas de bloqueo también se limitan a Azure OpenAI. No supongas que todos los controles ni el Customer Copyright Commitment se extienden a ellos ([Foundry Models](https://learn.microsoft.com/en-us/azure/foundry/concepts/foundry-models-overview), [CCC](https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/openai/customer-copyright-commitment), [listas de bloqueo](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/use-blocklists), [nota de transparencia](https://learn.microsoft.com/en-us/azure/foundry/concepts/safety-evaluations-transparency-note)).
- **Corte de claves no inmediato y nombre de la directiva.** Al deshabilitar la autenticación local, la puerta de enlace puede aceptar claves antiguas durante minutos u horas: documenta la espera en los runbooks y verifica el 401. Además, la directiva figura como «Azure AI Services resources should have key access disabled» y, en otras versiones, como «Foundry Tools resources…», porque el cambio de nombre está en curso ([deshabilitar claves](https://learn.microsoft.com/en-us/azure/ai-services/disable-local-auth)).
