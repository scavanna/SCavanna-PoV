# Qué está respaldado y cómo se construyó la matriz V3

**Corte: 18 de noviembre de 2026.** El Excel V3 incluye el catálogo de Microsoft Defender for Cloud for AI Services, su lectura de triage, las hipótesis de mapeo por alerta y los vínculos publicados para los 14 escenarios CAAT. Las fuentes y revisiones se conservan en `data\reference.json`; las decisiones propias se conservan en `data\policy.json`. No hay resultados de un cliente o tenant presentados como validación.

## Dos mapeos distintos

1. **Referencia:** Learn → escenario CAAT → IDs OWASP LLM 2025 y ATLAS citados por Learn. Se preservan IDs originales y, si MITRE documenta migración, se agrega el término vigente al lado. El catálogo oficial de ATLAS fuente de esta edición es [2026.10](https://github.com/mitre-atlas/atlas-data/releases/tag/v2026.10), con 16 tácticas y 221 ítems (129 técnicas, 92 subtécnicas). Si un enlace profundo no abre, buscá el ID desde la [matriz ATLAS](https://atlas.mitre.org/) o en el [YAML fijado](https://raw.githubusercontent.com/mitre-atlas/atlas-data/v2026.10/dist/v6/ATLAS-2026.10.yaml). La plantilla de Navigator del release determina el dominio de la capa.
2. **Operación:** `AlertType` → relación propuesta con un escenario/técnica/riesgo, y evidencia necesaria. Ni el vínculo oficial de CAAT a un marco ni la existencia de una técnica en ATLAS se heredan como una detección del producto.

| Disposición | Qué significa |
|---|---|
| `direct` | La señal coincide con la relación sin exigir evidencia externa adicional. Describe el intento, veredicto o indicador; no prueba impacto ni éxito. Vínculo elegible para etiquetado, después de la validación del piloto. |
| `conditional` | Requiere evidencia independiente explícita en la matriz; no se agrega etiqueta de marco por esta relación. |
| `context` | Pivote de investigación, no atribución. No se etiqueta el marco. |
| `no_attribution` / `unclassified` | Sin relación intencionalmente / tipo observado no clasificado aún. No son equivalentes y no se completan inventando cobertura. |

**Ejemplos.** Para jailbreak en Prompt Shields: el intento de inyección directa (`AML.T0051.000`) y el intento de jailbreak (`AML.T0054`) describen la señal, sin afirmar que el modelo obedeció. Para credenciales en respuesta: la señal aporta a CAAT-07 y a OWASP LLM02. `AML.T0085.002` solo si se verifica obtención de contexto/memoria; `AML.T0024` solo con evidencia de transferencia no autorizada vía API de inferencia. Para wallet: CAAT-05, `LLM10:2025` y `LLM06:2026` aportan la categoría; `AML.T0034` y denegación de servicio requieren evidencia adicional. Para una invocación de herramienta fuera de patrón: verificar intento abusivo antes de atribuir `AML.T0053`, y autoridad excesiva antes de invocar `LLM03:2026`.

**Versiones OWASP.** La [publicación OWASP LLM 2026](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10/tree/main/2026/final) es distinta del [OWASP Top 10 para aplicaciones agénticas](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/). `LLM03:2025` era Supply Chain y `LLM03:2026` es Excessive Agency. Ejemplo ATLAS: MITRE migró `AML.T0057` a `AML.T0085.002` y `AML.T0056` a `AML.T0085.003`, pero Learn refleja su propio momento de publicación. La matriz marca migraciones, no reasigna significado de forma automática. Ver las hojas **CAAT x marcos**, **Migraciones ATLAS** y **OWASP 2025 y 2026**.

## Qué reutilizar y dónde termina

| Recurso | Uso razonable |
|---|---|
| [MITRE `atlas-data`](https://github.com/mitre-atlas/atlas-data) y [Navigator](https://github.com/mitre-atlas/atlas-navigator-data) | Diccionario de referencia y formato de intercambio. Fijar release; no consultar `main` desde un playbook. |
| [OWASP GenAI crosswalk ATLAS](https://github.com/GenAI-Security-Project/crosswalk/blob/main/llm-top10/LLM_MITREATLAS.md) | Punto de comparación, no mapa de alertas. Tiene referencias antiguas como `AML.T0057`: resolver contra la versión de MITRE. |
| [Zero Trust Assessment AI_089](https://microsoft.github.io/zerotrustassessment/docs/workshop-guidance/AI/AI_089) y [Frontier AI Governance – módulo de AI threat protection](https://microsoft.github.io/frontier-ai-governance-rvas/modules/ai-threat-protection-shadow-ai/) | Guías Microsoft para validar ingesta y diseñar módulos de detección. No son mapeos ATLAS por alerta original MDC. |
| [MITREATLAS.yaml de Rod Trent](https://github.com/rod-trent/Security-Copilot/blob/main/Plugins/MITREATLAS.yaml) | Ejemplo comunitario de referencia en Security Copilot, no enriquecimiento por `AlertType`. Si se integra después, preferir una skill de solo lectura sobre `MDCAI_V3_Enriched` / `MDCAI_V3_Relations`, con fuente y versión explícitas y sin copiar evidencia. |
| [Rule pack de lizetpenamsft](https://github.com/lizetpenamsft/sentinel-llm-owasp2025-rulepack) y [ai-threat-detection de sagarm365](https://github.com/sagarm365/ai-threat-detection) | Ejemplos comunitarios para estudiar estructura KQL/etiquetado, no conectores oficiales ni un mapeo canónico de tipos MDC. Verificar cada supuesto y licencia antes de reutilizar. |
| [Defender-for-AI-use-cases de Daemarys](https://github.com/Daemarys/Defender-for-AI-use-cases) | Referencia comunitaria de flujos y diferencias entre protección y notificación. V3 no necesita instalar código de terceros. |

No usar una visualización de actividad para recomendar upgrades o afirmar que un control cubre todo un escenario. Para cambiar el estado a **validado**, registrar la configuración, origen de la evidencia, alcance, fecha y la versión; la hoja **Piloto** separa ese resultado de la actividad del workbook.
