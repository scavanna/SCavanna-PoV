# APC-122 — Lista de materiales de IA para sistemas críticos

**Tipo:** tesis ampliada por pregunta · **Estado:** propuesta editorial del corpus mayéutico, no concepto original GM-24 · **Ubicación:** `M6.2` (especialización explícita).

## Pregunta original (sin sustituirla)

`PC-122` · interrogativa: ¿Mantenemos una lista de materiales de IA (modelos, versiones, conjuntos de datos, instrucciones de sistema, herramientas, dependencias) para cada sistema crítico?

La formulación anterior es contenido de la fuente. La tesis siguiente no es una cita literal de esa pregunta: es el **enunciado declarativo ya registrado como propuesta** en el corpus de pre-ensayos.

## Tesis propuesta

Cada sistema de IA crítico debe tener una lista de materiales actualizada que registre modelo y versión, datos de entrenamiento y de recuperación, instrucciones de sistema, herramientas y dependencias, porque sin ella no es posible medir el impacto de una vulnerabilidad, reproducir un comportamiento ni saber qué sistemas afecta un cambio del proveedor.

## Tensión, prueba y limitación

**Tensión documentada:** la lista de materiales solo sirve si refleja el sistema que realmente opera, pero los componentes de IA cambian con frecuencia y algunos, como las instrucciones de sistema, no pasan por la gestión de configuración

**Desarrollo/investigación propuesto:** simular el aviso de una vulnerabilidad en una versión de modelo o en una biblioteca de orquestación y medir cuánto tarda el equipo en identificar, con sus listas, todos los sistemas críticos afectados

**Error a evitar:** trasladar sin cambios la lista de materiales de software tradicional a la IA, omitiendo datos de entrenamiento, instrucciones de sistema y herramientas que determinan el comportamiento

**Producto observable:** una plantilla de lista de materiales de IA con campos obligatorios, las listas completas de los sistemas críticos y un ejercicio cronometrado de búsqueda de impacto
