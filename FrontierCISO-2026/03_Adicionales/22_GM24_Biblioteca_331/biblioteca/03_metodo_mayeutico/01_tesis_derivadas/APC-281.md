# APC-281 — Controles mínimos y revisión anual de cada API expuesta

**Tipo:** tesis ampliada por pregunta · **Estado:** propuesta editorial del corpus mayéutico, no concepto original GM-24 · **Ubicación:** Unidad principal no asignada en la fuente; hay relaciones candidatas.

## Pregunta original (sin sustituirla)

`PC-281` · interrogativa: ¿Cada API expuesta tiene dueño, autenticación, autorización y límites de consumo, y se revisa al menos una vez al año?

La formulación anterior es contenido de la fuente. La tesis siguiente no es una cita literal de esa pregunta: es el **enunciado declarativo ya registrado como propuesta** en el corpus de pre-ensayos.

## Tesis propuesta

Cada API expuesta debe contar con un responsable nombrado, autenticación, autorización por objeto y por función, cuotas de uso y una revisión como mínimo anual, todo registrado en un inventario verificable. Las API sin dueño o sin límites forman una superficie de ataque que crece con cada integración sin que nadie esté obligado a cerrarla.

## Tensión, prueba y limitación

**Tensión documentada:** publicar API rápidamente impulsa integraciones y negocio, pero cada API nueva sin dueño ni revisión sigue activa más allá del proyecto que la creó y de quien conoce sus permisos

**Desarrollo/investigación propuesto:** contrastar el inventario declarado de API con el tráfico observado en las pasarelas y verificar, para las no registradas, quién las mantiene, cómo autentican y qué límites de consumo aplican

**Error a evitar:** suponer que una pasarela de API garantiza por sí sola autenticación, autorización y límites adecuados, o que una API interna no requiere los mismos controles

**Producto observable:** un inventario de API expuestas con dueño y controles verificados, un registro de revisiones anuales con hallazgos y pruebas ejecutadas de autorización y de límites de consumo
